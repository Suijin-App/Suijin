## What was built

### Phase 1: diff line notes
- **Model and migration.** `DiffNote` is in `Packages/MercuryCore/Sources/MercuryCore/DiffNote.swift`. Its fields follow Orca's `DiffComment`:
  - `workspaceID`, plus `worktreeID?` (nil means the main checkout)
  - `filePath`, `oldPath?`, `startLine?`, `lineNumber` (0 means the whole file)
  - `body`, `createdAt`, `updatedAt?`, `sentAt?`
  - `scope` (`uncommitted` or `branch`) and `diffIdentity?`
  - `edited(body:)` clears `sentAt`.

  The migration is `v3_diff_note` in `Migrations+DiffNotes.swift`. It cascades from the workspace and the worktree, and a CHECK constraint enforces a valid line range. The store API follows the contract: `diffNotes(worktreeID:)`, `save(_:)` (rejects an empty body or a bad range) and `deleteDiffNote(id:)`. I also added `diffNotes(mainCheckoutOf:)` for git main checkouts.
- **Formatter.** `DiffNoteFormatter` in MercuryDiff is an exact port of Orca's format. It escapes `\` first, then `"`, CR and LF. The location line is `Scope: file`, `Lines: a-b` or `Line: n`, and notes are joined by one empty line. The tests compare against hand-written strings, including a raw-string escape case and CRLF.
- **Gutter interaction.** Hovering a line (text or gutter) shows a "+" (SF Symbol, accent colour). You can drag in the gutter to pick a range; the range stops at hunk gaps (Orca's clamp rule) and auto-scrolls. There is also an "Add Note on lines a–b…" item in the context menu, so lines can be noted with the keyboard.
- **Composer and cards.**
  - Zones are inserted between TextKit 2 lines using paragraph spacing on the anchor row, and the zone view is a subview of the text view. The text itself is unchanged, so selection, copy and find still work.
  - Composer keys: ⌘Return saves, Escape cancels.
  - Cards show where the note points, a Sent or Unsent badge, Edit and Delete. A "Lines changed" badge marks stale notes.
  - File notes, and notes whose lines are no longer in the diff, show in a header above the diff, which also has a "Note on File" button.
- **Stale notes.** `diffIdentity` is a hash (FNV-1a) of the noted lines' text at creation. A note is stale when the lines at those numbers no longer match.
- **Sending notes.** The send menu is `App/Features/Diff/DiffNotesSendMenu.swift`, a toolbar Menu with a count badge:
  - "Send to <session>" for each running session of the context. It pastes the unsent notes as one bracketed paste through `SessionRuntime.paste(_:pressReturn:)` in `App/Features/Diff/SessionRuntime+Paste.swift`.
  - The paste is refused if the program has not turned bracketed paste on, so lines can never run one by one.
  - After sending, the notes get `sentAt` and the app switches to that session's tab.
  - "Copy Unsent Notes" copies them instead.
  - "Show Only Unsent Notes" is the Unsent filter. It narrows the file list and the notes shown.
  - "Send Notes Automatically" sends Return 200 ms after the paste.
- **Settings.** `DiffNotesSettingsSection` (in the same file) is a ready Settings `Section` bound to the same preference (`@AppStorage("diff.notes.sendAutomatically")`). The controller can place it in `SettingsView`.

### Phase 2: side-by-side diff
- **Layout.** `SideBySideLayout` pairs each run of deleted lines with the added lines that follow, fills the shorter side with padding rows, and keeps a "no newline" marker under its own line. `DiffLayout` gained a generic line-based init, a `.padding` row kind and `contextSide`, so each column highlights from its own version.
- **Word diff.** `WordDiff` tokenises lines and keeps the longest common subsequence, after first stripping the common prefix and suffix. It falls back to prefix/suffix only on very long lines. If less than 30% of the lines is shared, nothing is marked. Marks are drawn as TextKit 2 background rendering attributes.
- **View.** `SideBySideDiffView` holds two non-wrapping `DiffTextView`s, laid out in full so rows are positioned exactly. Vertical scrolling is synchronised through bounds notifications; horizontal scrolling stays independent. Gutters show old numbers on the left and new numbers on the right.
- **Notes in side by side.** Notes go in the right column, and the left column gets spacers of the same height so rows stay aligned.
- **Layout picker.** A segmented Layout picker in the Changes toolbar is saved in `@AppStorage("diff.layout")`. Below `SideBySideDiffView.minimumWidth` (760 pt) of diff pane, the view falls back to unified and shows a quiet "Too narrow for side by side" label, with the full explanation as help text.

## Notes and deviations
- A DEBUG-only screenshot hook, `-MercuryDiffNoteDraft <line|a-b>`, opens the composer once. It follows the existing `-MercuryInitialTab` pattern and exists because pointer events cannot be synthesised here (no Accessibility trust).
- A note anchored to an empty last row of a diff cannot get a gap, because there is no character to hold the spacing. Such notes show in the file header instead of being lost.
- The "Send notes automatically" and layout preferences live in UserDefaults through `@AppStorage`, not in the `setting` table, because `SettingKey` is in `AppModel.swift`, which I do not own.
- With the inspector open on a screen about 1512 pt wide, the diff pane is under 760 pt, so side by side falls back to unified (and says so). It shows once the inspector is hidden or the window is wider.
