## Design notes

- Refresh is gentle:
  - Status is re-read every 5 s, only for the visible context and only while Mercury is the active app.
  - The pull request is read when a context opens (skipped if it was read in the last 30 s), from the Refresh button, and every 2 min for the visible context only.
  - Each sidebar badge reads its pull request once.
  - `gh auth status` is cached per host for 5 min.
- Generation runs with the context's account: the latest session of that agent in the context, else the provider's default (`AccountsController.launchEnv`). The PATH is the login shell's. The Generate menu defaults to the app's default agent, with Claude/Codex choices.
- A commit failure leaves the draft untouched. The output sheet is presented by the view (inspector or toolbar) that started the action.
- Creating a PR pushes first when needed. If gh reports that a PR already exists, the app opens it instead.
- DEBUG-only hooks for screenshots: `MERCURY_GH_PATH` (fake gh), `-MercurySourceControl commit|pullRequest|commitError`, `-MercuryShowInspector YES`, `-MercuryShowSidebar YES`.

## Concerns

1. **String catalog.** `App/Resources/Localizable.xcstrings` is shared and outside my ownership, so I did not edit it. All UI text goes through `Text("…")`/`String(localized:)`, but the new keys are not in the catalog yet. A single extraction pass (for example, building once in Xcode) after the branches merge would add them.
2. **Folder workspaces.** Phase 3 step 5 ("Initialize Git" `ContentUnavailableView` for folders) is not implemented. The hooks are shown only for git contexts, and you asked to keep it that way. Adding the folder state would require editing `WorktreeInspector.swift`, which I don't own.
3. **Real PR not tested.** "Create a draft PR on a test repository" from phase 4 was not run against GitHub, because you asked for no real PRs. The flow is covered by the fake `gh` and the captures.
4. **Codex config.** `--ignore-user-config` means the user's custom model or provider settings in `config.toml` are not used for generation. I chose this for isolation: it keeps MCP servers, `notify` (which Branch C configures) and hooks from running.
5. **Shared scratchpad.** Another branch overwrote my `scratchpad/tools/shot.sh` at one point. All my artifacts now live under `scratchpad/branch-b/` and `scratchpad/DD-B/`. I re-ran `scripts/bootstrap.sh` twice to pick up new files; this includes files added by Branch C, which is idempotent.
