## Hook design
- Settings shape (the same as Orca's `CLAUDE_EVENTS`): `{"hooks": {Event: [{"hooks": [{"type":"command","command":…,"timeout":10}]}]}}` for SessionStart, UserPromptSubmit, Notification and Stop. PreToolUse is left out on purpose: it fires on every tool call and adds nothing to the status logic.
- The command is `/bin/sh -c '…'`. It redirects all of its own output to /dev/null, because stdout from UserPromptSubmit and SessionStart hooks becomes model context. If `MERCURY_HOOK_EVENTS` is empty it only drains stdin. Otherwise it strips CR/LF from the JSON and appends it with a single `printf`. It always exits 0. Tests run the exact command string through /bin/sh and cover: pretty-printed input becoming one line, quotes, empty stdin, an unset variable, an unwritable path, and no stdout or stderr output.
- Events file: `<dataRoot>/hooks/events/<UUID>.jsonl`. Env: `MERCURY_HOOK_EVENTS`, `MERCURY_SESSION_ID`.
- The watcher watches the parent directory until the file exists. It consumes only complete lines, so a partial last line is re-read once finished. It restarts at offset 0 on truncation and goes back to watching the directory on delete or rename. `readExisting: false` skips history. All state is confined to a serial queue.

## Status tracker semantics
- starting → running on the first output. running → idle after 8 s without output; `tick(now:)` applies this.
- Notification (any type except `auth_success`) and PermissionRequest → waitingForInput. Stop and StopFailure → idle. These two are "quiet" states: plain output, such as a redraw, does not leave them. They end on UserPromptSubmit, or on output that follows user input recorded after the state was entered.
- An idle state reached by timeout leaves on any output.
- `noteExit(code)` → `.exited(code)`, and `nil` → `.failed`. Terminal states never change. `onChange` fires only on real transitions.

## Notes
- Codex status is based only on output timing. Orca installs Codex hooks into a managed CODEX_HOME `hooks.json`, which needs trust hashes in config.toml. That belongs with the phase 6 Codex home work, not here.
- `loginShellPATH` wraps PATH in markers, so banners printed by the user's profile cannot corrupt it. It finishes as soon as both markers have arrived, so a background grandchild holding the pipe open cannot stall it. On a timeout or failure it falls back to `~/.local/bin:/opt/homebrew/bin:/opt/homebrew/sbin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin`. The marker command was checked against the real login zsh by hand; the tests use fake shells.

### M3: login-shell PATH now reads `.zshrc`
- `loginShellPATH()` now calls `resolveShellPATH`. It tries `<shell> -l -i -c` first, then `<shell> -l -c`, then `fallbackPATH`, each with a 5 s timeout. The result is cached as before.
- The probe is spawned with `posix_spawn` and these settings:
  - It runs as a new session leader (`POSIX_SPAWN_SETSID`), so an interactive shell has no controlling terminal. Job control, `/dev/tty` reads and the p10k instant prompt cannot block it.
  - stdin and stderr go to /dev/null, so `compinit`- or `read -q`-style prompts get EOF.
  - It inherits no file descriptors (`POSIX_SPAWN_CLOEXEC_DEFAULT`), uses default signal dispositions and an empty signal mask, and gets `TERM=dumb`.
- PATH is still read from between markers, and the printf now builds the marker at run time. The literal never appears in the command line, so a shell that echoes the command cannot produce a fake match.
- Capture stops once both markers have arrived. This matters on the dev machine: the marker arrives about 1.5 s into an interactive zsh, but the shell takes another ~10 s to exit. When capture ends, whatever remains in the child's process group gets SIGTERM, then SIGKILL one second later. The child is always reaped.
- New tests:
  - A temp `ZDOTDIR` whose `.zshrc` prints a banner and escape codes, asks a `read -q` question and prepends a directory to PATH. The interactive probe returns that directory first; the login-only probe does not include it.
  - Noisy output with half a marker.
  - The detached-session, non-tty stdin and `TERM=dumb` invariants.
  - Early finish that kills a lingering background child.
  - A child that ignores SIGTERM, left behind by a shell that already exited, is SIGKILLed.
  - The timeout case.
  - Falling back from interactive to login to the default.
- Not in this package: the reviewer also suggests passing the resolved PATH into the agent's launch env, so an npm-installed `claude` can find `node`. Agents start through `ShellLaunch` (MercuryTerminal) and the App. The App can add `EnvPatch(set: ["PATH": await AgentCatalog.loginShellPATH()])` to the env given to `AgentLaunchSpecBuilder.make`. Alternatively, `ShellLaunch.command` could use `-l -i` the same way.

### L4: event logs are private
- `ClaudeHooks.install` creates `hooks/` and `hooks/events/` with mode 0700, and tightens them if they already exist.
- The hook command starts with `umask 077`, so a file the hook creates is 0600 even when its parent shell's umask is 000 (tested).
- New `Installation.prepareEventsFile(sessionID:)` creates the session's file as 0600, or chmods an existing one. The App should call it before launching a Claude session, next to starting the watcher.
- `HookEventWatcher` creates a missing parent directory as 0700. It does not change an existing directory.

### `--` before the initial prompt: not changed
- I could not check this without starting a real session, and that would send a prompt. In both `claude -- --x` and `codex -- --x`, the text after `--` becomes the prompt, so a successful test starts an interactive session.
- Also, Commander-style parsers (claude) look up subcommands among the arguments after `--` too. A leading `--` would probably not stop a prompt like "update" from running the subcommand anyway.
- The current behaviour stays: `--` is added only when the prompt starts with `-`. The one-word subcommand-name edge case is still open. The App could block or quote such prompts in the UI if needed.
